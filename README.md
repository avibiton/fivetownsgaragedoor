# Five Towns Garage Door — fivetownsgaragedoor.com

Production website for Five Towns Garage Door (578 Central Avenue, Cedarhurst, NY 11516 · (516) 490-0931).

**Deploy the contents of [`site/`](site/). It is plain static HTML/CSS/JS: no server-side code, and no Node or Python needed in production.**

## Legacy URLs are preserved exactly

Every URL indexed since 2013 is served at the same path, with the same filename and letter case:

```
/index.html                  /repair.html               /cedarhurst-garage-door.html
/installation.html           /openers.html              /hewlett-garage-door.html
/residential.html            /commercial.html           /lawrence-garage-door.html
/liftmasteropeners.html      /Genieopeners.html         /woodmere-garage-door.html
/LocationServices.html       /faq.html                  /inwood-garage-door.html
/contact.html
```

`/` and `/index.html` both return 200. The homepage canonical is `https://fivetownsgaragedoor.com/index.html`, matching the legacy site and sitemap. Never add a redirect between `/` and `/index.html`.

### Redirects (all single-hop 301s to the final URL)

| From | To |
|---|---|
| `/contact.php` (any scheme/host) | `https://fivetownsgaragedoor.com/contact.html` |
| `/error.html` (any scheme/host) | `https://fivetownsgaragedoor.com/index.html` |
| `http://fivetownsgaragedoor.com/<path>` | `https://fivetownsgaragedoor.com/<path>` |
| `http(s)://www.fivetownsgaragedoor.com/<path>` | `https://fivetownsgaragedoor.com/<path>` |

The paths and query strings are preserved. The rules are implemented in:
- `site/.htaccess` (Apache / LiteSpeed / cPanel)
- `site/_redirects` (Netlify)
- `vercel.json` (Vercel)

## Deploying

- **cPanel / Apache / LiteSpeed:** upload everything inside `site/` into `public_html/`, including the hidden `.htaccess`. The host needs `mod_rewrite`; `mod_headers`, `mod_expires` and `mod_deflate` are optional and wrapped in `IfModule`.
- **Netlify:** connect the repo. `netlify.toml` publishes `site/` with no build command. In Site settings, keep **Pretty URLs / asset optimization off** so the `.html` URLs are never rewritten. Add both the apex and `www` domains, with the apex as primary.
- **Vercel:** import the repo. `vercel.json` sets the output directory to `site/` and turns off `cleanUrls`. Add both domains, with the apex as primary.
- **Cloudflare Pages:** the `/contact.php` and `/error.html` rules in `_redirects` work. Handle www→apex with a Cloudflare Redirect Rule and turn on "Always Use HTTPS".
- After HTTPS is confirmed on the live domain, you can enable HSTS. The header is ready but commented out in `.htaccess`.

### After launch
1. Run `tools/test_redirects.sh` with no arguments. It tests the live domain, including case sensitivity.
2. Run `python3 tools/qa.py https://fivetownsgaragedoor.com`.
3. In Google Search Console, resubmit `https://fivetownsgaragedoor.com/sitemap.xml` and use URL Inspection on the town pages.
4. Update the Google Business Profile with the same NAP (name, address, phone) and website URL.

## Editing the site

The source pages are in `src/pages/`, one file per URL. The file name is the URL. Shared header, footer, head tags, JSON-LD and the sitemap are generated by `build.py`, which uses only the Python 3 standard library:

```bash
python3 build.py                   # rebuild site/
python3 build.py --check faq.html  # validate one page without writing
```

- Page metadata (title, description, OG, breadcrumbs, phone line, sitemap priority) lives in the `<!--META {...} META-->` block at the top of each page.
- **FAQ schema is generated from the visible `<details class="faq-item">` accordions**, so structured data always matches what visitors see. Never hand-write FAQ JSON-LD.
- Business data (NAP, phone lines, hours, service area, offer catalog) is defined once in `build.py`.
- The component reference is in `docs/COMPONENTS.md`, and the pre-rebuild audit is in `docs/SEO-AUDIT.md`. The original production files are kept untouched in `legacy-source/` for reference. That folder is not deployed.
- Commit the rebuilt `site/` along with source changes.

## Analytics / call tracking

Every phone link has `class="js-call"` and a unique `data-cta`. Examples: `topbar-call`, `header-call`, `hero-call`, `sticky-call`, `footer-call`, `<page>-final-call`, `cedarhurst-hero-call`. When a GA4 / GTM / call-tracking ID is available, one delegated click listener on `.js-call` can report `data-cta`. No third-party tracking scripts are included.

## Service request form

`contact.html#request` has a service request form, but **no form-processing backend exists**. The form therefore opens the visitor's email app with the request pre-filled, addressed to service@fivetownsgaragedoor.com, and says so on the page. Nothing is silently discarded. To accept submissions directly, point the form's `action` at a real endpoint (Netlify Forms, Formspree, or a PHP handler) and remove the `submit` handler in `site.js`.

## Performance

The site runs without any framework. It loads one minified CSS file (about 36 KB, about 8 KB gzipped), one small deferred JS file (menu and form only), and two self-hosted variable fonts (Oswald and Source Sans 3, latin subset, SIL OFL) that are preloaded. Icons are an inline SVG sprite. There are no raster images above the fold.

Lighthouse (mobile, local) scored 100 for Performance, Accessibility, Best Practices and SEO on all 16 pages, with CLS 0.

## Hero photography

Every page hero has a full-bleed garage-door photo behind a dark overlay. Each is a responsive `<picture>` in AVIF and WebP at 768/1280/1920 px, with explicit dimensions and a high-priority preload. The photos are **licensed Unsplash stock, not company jobs**; credits are in `docs/PHOTO-CREDITS.md`. To use real job photos, replace the files in `src/static/assets/images/hero/` (same names), or change the keys in `content_data.py`, then run `python3 build.py`.

## Google reviews

The reviews come from the Google Business Profile "Five Towns Garage Doors": https://maps.google.com/?cid=13986575148892573272

- The rating (4.7 from 15 reviews, as of Sept 2026) appears in the top bar, the footer and each reviews section.
- The homepage shows all 14 five-star reviews, verbatim. Every other page shows 3 of them just before the final call-to-action.
- The data lives in `content_data.py` (`GOOGLE_RATING`, `GOOGLE_COUNT`, `GOOGLE_AS_OF`, `REVIEWS`). **Update it when the profile changes**, because the hard-coded count goes stale.
- The site deliberately has no Review or AggregateRating structured data. Google ignores review markup a business adds about itself on its own site, and it can trigger a manual action.
